# CLAUDE.md

Working conventions for `PXL-Digital-Application-Samples/pxl-classroom`.

**This file is instructions only.** What the system *is* → [ARCHITECTURE.md](ARCHITECTURE.md). How to operate it → [RUNBOOK.md](RUNBOOK.md). How it looks → [DESIGN.md](DESIGN.md). **Why any rule below exists** — what broke, what was measured — → [LESSONS.md](LESSONS.md), searchable by the rule's own wording. Read the lesson before changing or arguing with a rule; nearly every one is here because it already went wrong.

## Git

- **No pull requests.** Commit and push directly to `main`. Never branch "to be safe".
- End commit messages with the standard `Co-Authored-By` trailer.
- **A `Co-Authored-By` address is an identity claim, and GitHub resolves it by EMAIL, not by the name beside it.** Whoever holds that address becomes a contributor to this public repository. `Co-Authored-By: Antigravity <antigravity@google.com>` credited a stranger in New York on seven commits, and still does — removing it means rewriting 400 commits and force-pushing a protected branch. Use a vendor's published noreply address or an `@users.noreply.github.com` one; never a plausible-looking mailbox at a real domain. `tests/commit-trailers.test.mjs`.
- **Push with `$env:GITHUB_TOKEN=""; git push origin main`** (PowerShell) — a dummy token in the environment otherwise fails the auth.
- **No backticks in a double-quoted `git commit -m`.** The shell substitutes them before git sees the string and the fragment vanishes silently; `main` blocks force-push so it cannot be amended. Use single quotes for any `-m` containing a backtick, `$` or `!`.
- **A commit subject is an input to the release, and `.husky/commit-msg` now enforces it.** The version and the release notes are derived from these subjects, so `fixed:` instead of `fix:` releases nothing and appears in no notes — silently, and with no pull request anywhere to catch it. The allowed types are **read out of `.releaserc.json`** by `commitlint.config.js`, never listed twice: a type the hook admits that the release config has no opinion about is a commit that vanishes. `style` sat in exactly that state, used four times and declared nowhere. `tests/commit-types.test.mjs` checks both directions and the history.
- **A `prepare` script must survive `npm ci --omit=dev`, which fourteen production workflows run.** `--omit=dev` skips devDependencies and **still runs `prepare`**, so a bare `"prepare": "husky"` exits 1 and takes acceptance, the nightly, publishing and the deploy with it. `husky || exit 0` — and `exit 0` rather than `true`, which is not a `cmd.exe` builtin.

## Working style

- Be terse and concrete. Do things rather than explain them; give exact values and clicks when the user must act.
- Don't ask for command approval — permissions bypass in `.claude/settings.local.json`.
- **NEVER edit a file through a shell heredoc.** No `python3 - <<'EOF'`, no `cat > file <<'EOF'`, no `node -e`. Use **Edit** for targeted replacements and **Write** for whole files: the shell and the interpreter both process escapes before the code runs, so regexes and string literals are silently mangled. If a repo-wide sweep is genuinely unavoidable, **Write** the script to a real file, run it, delete it. Bash stays correct for reading, searching, git and tests.
- **A scripted transform must be verified by something that does not share its logic.** A checker built from the same function as the transform validates its own bug.

## Linting

- **`npm run lint` is the only lint command, and CI runs exactly it.** `scripts/lint.mjs` owns all three checks (eslint, `scripts/workflow-lint.mjs`, actionlint + shellcheck); `ci.yml` calls nothing else.
- **actionlint and shellcheck are pinned identically** — a release asset fetched into gitignored `.tools/` and verified against a SHA-256 in `scripts/lint.mjs`. Never from npm, never by piping a script from a branch into bash. A tool that cannot be obtained, or a platform with no pinned digest, **fails** the run. There is no skip flag.
- **Keep every `run:` block under 3500 bytes.** Over ~4 KB actionlint deadlocks on Windows while CI stays green. Split the step; do not raise the cap.
- A genuine shellcheck false positive gets `# shellcheck disable=SC<code>` with a comment saying why.

## Documentation

- **ARCHITECTURE.md, RUNBOOK.md, ADMIN.md and INSTALL.md describe the system as it IS.** A past incident belongs in LESSONS.md, never in them.
- **The operational docs are split by audience, and a procedure goes where its reader is.** `RUNBOOK.md` is the lecturer's (publishing, deadlines, grading, a student who is stuck); `ADMIN.md` is the administrator's (onboarding an org, budgets, App permissions, incidents); `INSTALL.md` is the one-time institutional setup. A procedure filed under the wrong audience is invisible — "Invitation Exposure is failing" sat inside the *Claim keypair* setup subsection for months.
- When architecture or procedure changes, update `ARCHITECTURE.md`, `RUNBOOK.md` and this file **in the same commit**. A new rule here gets its story in `LESSONS.md` in that same commit.
- **A reference table lives in exactly one section; everywhere else links to it.** Every doc defect found in the 2026-08-31 audit was one fact written twice with one copy updated — a permission table that had drifted four ways, tokens spelled as dark-only hex, "one GitHub App" after there were two. Before writing a list down, check whether it already exists somewhere.
- **Section numbers are a public API — count the references before renumbering one.** Code comments, tests and workflow YAML cite them (`§4.3.2` has 62 references), and a reference to a section that no longer exists renders as ordinary text. Sweep on an exact string, then verify against the headings the documents actually declare.
- Do not add top-level planning, progress or review documents — the project stopped using them. `OPEN-ITEMS.md` is the one exception and is not a plan: it is a standing register of known infrastructure gaps, every entry carrying the command that says whether it is still open. Nothing goes in it that a procedure could state instead, and an entry is closed from evidence, never from memory.

## Credentials and workflow safety

Breaking one of these has cost this project a real incident. They are not style.

- **No value is composed into a script, anywhere.** `${{ }}` is substituted into the script *text* before bash or the JS parser sees it, so the question is never "is this attacker-reachable" but "is this a literal I wrote". Everything else goes through `env:`. Applies to composite `action.yml` too.
- **No attacker-controlled text may reach a shell on a broker.** A broker is public and holds a credential; the issue *body* is never read there — the hub fetches and validates it.
- **The student authored the acceptance issue, so a comment or a close EMAILS them.** The outcome is a **label** (`lib/acceptance-labels.mjs`) and the broker redacts and locks but does not close. Metadata is silent, a label cannot be applied without write access, and labelling a locked issue works where commenting returned 403. Two labels exist and no more: a per-reason one is filterable, which would publish which named students are not on the roster.
- **A `client_payload` address is validated on the WRITE path too.** `broker_repo` is `owner/repo` and the owner must equal the dispatched org — `lib/broker-issue-target.mjs`, never a hand-rolled `split("/")`. The read path had the check for months while the hub's `issues: write`-on-every-org token wrote to whatever a dispatch named.
- **Hub credentials only run from `main`.** Every job reading `PXL_APP_PRIVATE_KEY`, `PXL_INVITE_SIGNING_KEY`, `PXL_CLAIM_PRIVATE_KEY` or `PXL_BROKER_PRIVATE_KEY` declares `environment: provisioning`. Never put them in workflow- or job-level `env:`. They are environment secrets with **no repository-level copy**.
- **Every dispatchable workflow that reads a hub credential rejects a `[bot]` actor as its first step** — unless another workflow legitimately dispatches it, or a guarded job sits upstream in its `needs:` graph.
- **The provisioning App's key never reaches a broker.** Brokers hold the *broker* App's key: hub repo only, `contents: write` only. Publishing fails closed if it is unset rather than falling back.
- **What a signed request ASKS FOR must be inside the signature.** One secret now mints two titles — `pxl-accept:` and `pxl-confirm:` — and the signature covers `<kid>.<payload>`, so the prefix sits outside it and rewriting one into the other would have verified perfectly. The purpose is folded into the signed *subject* instead (`confirm:<id>` vs `<id>`), which costs no wire-format change — and that constraint is absolute here, because every broker ever published checks the hub out at `main`, so a new payload byte breaks every live acceptance at once. The verifier returns the purpose it checked and the broker forwards *that*; re-reading the prefix downstream is reading an unverified string that happens to agree. Absent means the original meaning (`accept`), an unknown value **fails** rather than guessing. `lib/acceptance-signature.mjs`, `tests/confirm-purpose.test.mjs`.
- **A second door on one credential inherits that credential's lifetime, or it needs its own — and its own is the one nobody closes.** The confirm-email link rides the assignment's keypair, nonce and broker so `INVITE_ENABLED` and nonce rotation already end it. A standing per-org receiver would have been the broker App's key on a public repo forever, which is the incident `close-acceptance.mjs` exists to have ended. Pay the cost that comes with it — there must be a live assignment to carry a link — and write it down rather than engineering it away.
- **Every action is pinned to a SHA**, never a tag. App tokens are minted with `client-id`, never `app-id`.
- **Credentials never appear in a git command line or a remote URL.** Use `http.<host>/.extraheader`, and unset it in a `trap … EXIT` — `git config` writes the header into `.git/config` exactly as an embedded credential would, so the on-disk copy is the residual and the step that dies mid-push must not be the one that leaves it behind.
- **`.tools/`, `.claude/` and `.env*` stay gitignored.** GitHub push protection blocks provider tokens, but not the P-256 keys this system mints.
- **Two entry points run with NO `npm ci`** — `scripts/verify-invite-token.mjs` on the broker and `scripts/scaffold-control-repo.mjs` in `setup-org.yml`. A bare specifier anywhere in either import graph is a total outage, not a slow start. `#deployment` is the live trap.
- **`git add <dir>/` is fatal when the directory is absent** — exits 128 and stages nothing, *including the pathspecs that did match*. `mkdir -p` immediately before it, within four lines. **`|| true` is not the fix, it is the worse failure**: the step then stages nothing, `diff --cached --quiet` is true, and it exits 0 reporting "no changes". `git add -A` is safe — no pathspec to miss.
- **`gh` writes API errors to stdout.** Guard on the exit code, then validate the shape; `--jq` prints the string `null` for a missing field.
- **Narrowing a GitHub App permission is instant; restoring one needs every org owner to approve.** Check the code, not the changelog, before removing one.

## Rules that keep being rediscovered

- **One page is not the list.** A list endpoint returns a page; a statement about the whole collection needs the walk. Where a walk is capped, the capped case may not report `ok`.
- **A GitHub login is compared and indexed lowercased** — `lib/github-login.mjs`, never a hand-written `.toLowerCase()`. The spelling a lecturer types into a roster CSV and the one GitHub dispatches are the same account; four indexes in `report.mjs` keyed the raw string and a single student became two rows.
- **A "pick ours out of the list" helper returns null when ours is absent.** `|| list[0]` turns "not installed" into somebody else's installation, and "no grading run" into full marks off an unrelated green check.
- **A deployment.yml value is read, never re-spelled.** JavaScript imports `#deployment`; YAML cannot, so `tests/deployment-literals.test.mjs` checks the workflows and the CORS Worker against it.
- **Whatever `publish` switches on, something has to switch off.** `INVITE_ENABLED` went `true` at publish and was never set back, so every broker an org had ever published still booted a runner for acceptance attempts — on a finished exam, five days after its deadline, for a run the hub refuses as `rejected:past-deadline`. Asking the same question of the rest found the broker App's **private key** sitting on every finished broker, a public repo, with no expiry. `scripts/close-acceptance.mjs` does both when the nightly finalizes: close the door, **then** delete the key — never the other way round, or a broker still accepts and can no longer dispatch.
- **A safety net that runs as a side effect of something else has a hole the shape of that something else.** The dashboard reconciliation lived in `report.mjs`, so it only ran when a report was generated — and reports are generated for `published`/`closed` assignments only, so an org whose remaining assignments were all draft or archived never reconciled and kept a deleted assignment's card for ever. `pruneMissingAssignments` (`lib/dashboard-aggregate.mjs`) is the shared decision; `scripts/prune-dashboard.mjs` runs it standalone in `regenerate-dashboard.yml` under `if: always()`. Found because cleaning up a live test needed a hand-edit no procedure could perform — which is the tell.
- **The template is pinned by `repository_id`, and a rename is not a replacement.** GitHub redirects a renamed repository and keeps the id, so pinning the *name* would break an ordinary tidy-up; the id catches what a name cannot — deleted and recreated, or transferred with the name reused, which puts half a cohort on different starter code silently. The pin belongs to the name it sits beside, so a *different* template is a new pin rather than a mismatch (`resolveTemplatePin`). The form warns and saving adopts (re-typing the same name reaches the same mismatch, so the field is a loop with no exit); publish refuses; **provisioning refuses**, because publishing does not happen again while a cohort accepts. `buildAssignmentDoc` rebuilds `template`, so the pin has to be passed in or the next unrelated edit deletes it — one level below the top-level sweep that guards this. It is read at save, never written into `form` on probe, or opening an unpinned assignment looks edited.
- **A pre-flight asks with the credential that will do the work, or it is decoration.** A template in another org must be PUBLIC: `generate` is one call needing read on the template and create in the course org, and the App's token is minted per installation — measured 2026-09-07, a public foreign template works (ownership is irrelevant; the token is not the lecturer) and a private one is 404 *even where the App is installed on that org too*. The Admin Panel probed with the **lecturer's** token, which can see their own private repository, so the badge went green on the one case that cannot work and provisioning failed after the student had accepted and spent a slot of `max_acceptances`. `lib/template-source.mjs` is the one judge; the form blocks the save and `scripts/check-publish-preflight.mjs` re-asks it in `publish-assignment.yml` with the org's installation token. That step also warns — never refuses — when a **free** org will blunt this assignment's deadline (`assignmentFreezePlanFinding`); it is read live and stored nowhere, because Team is free for educators and a recorded verdict would outlive the fact.
- **A staff surface is gated on demonstrated capability, never on visibility.** An org reaches the switcher for anyone whose App installation touches it — accepting one assignment is enough — so `staff = hubWritable || orgAdmin`, both positive signals, and an unreadable answer refuses. A 404 from a private repo is *not* "it does not exist": that read told a student their org needed setting up and badged them Lecturer. `tests/dashboard-authorization.test.mjs`, `tests/e2e/58`.
- **A check run that did not run is not a zero.** A job skipped by an `if:` gate is a real check run at a real commit — named after the grading job, so the picker picks it — with `conclusion: skipped` and no annotations. Only `success` and `failure` are grading attempts that happened (`graded` in `lib/check-run-score.mjs`); everything else is reported as a failed read naming the student. A cloud exam grades one commit on purpose, because the sandbox is gone afterwards, so `submission_marker` (`lib/submission-marker.mjs`) says which commit's run to read — and that is *all* it says: not what is preserved, not what is late.
- **Unreadable is not evidence, and a 200 can be unreadable.** A read that failed yields *no* check, never a green one and never "none found" — and neither does a read whose *authority* is unestablished. `GET /user/repository_invitations` answers `200 []` to a student who has a pending invitation, so "we asked and there was nothing" was never knowledge; `frontend/src/lib/invitation-evidence.js` is the one judge and a match is the only proof.
- **Absent and empty are different answers.** A truthy check silently re-imposes a rule someone deliberately removed.
- **A JSON Schema `default` is a WRITER, so a tri-state field may not have one.** `lib/validate.mjs` runs Ajv with `useDefaults: true`, which **mutates the document being validated** and fills the field in — so validating writes an answer nobody gave. Harmless where the default is what every reader already assumes for an absent field (`assignment_type: individual`); a defect wherever absent and the default are *different* answers. `org_scoped_lock` (absent = the default under `block`, `false` = opt out) and `template_grades` (absent = nobody was asked, `false` = they said no) were both given one, two days apart, and both collapsed their own tri-state — the second turning "never asked" into "answered no", which hides the grading controls from exactly the assignments the evidence fallback exists for. Caught by a live drill printing a field that is not in the file. `tests/schema-defaults-are-writers.test.mjs` pins the set validation may invent, each with the reason it is the same answer.
- **A schema field spelled wrong compares as a constant.** Report rows are `additionalProperties: false`, so `s.status` (the field is `submission_status`) is `undefined` on every row and `!== 'x'` is always true — which counted a whole roster as having accepted. `===` fails closed and is survivable; `!==` fails open. `tests/report-row-fields.test.mjs` sweeps comparisons against undeclared row fields; a dead `||` fallback is deliberately not flagged.
- **When one name is spelled in two files, a test derives one spelling from the other.** Same defect as the rule below, across a file boundary, where no compiler and no reviewer sees both halves. A step output is spelled three times — `setOutput("invited")`, `action.yml`'s `value:`, the workflow's `if:` — and a typo in any of them yields `''`, so `if: '' == 'true'` is false, the run is **green**, and the feature never happens. Inputs were guarded in both directions for years while outputs were not, and outputs are the worse half: a wrong input is an error, a wrong output is silence. `tests/workflow-output-contract.test.mjs` closes script → `action.yml` → workflow; `tests/table-colspan.test.mjs` rebuilds a colspan from the columns the template actually renders. Do not write a more careful count — derive it.
- **Two conditions that must agree are ONE named boolean.** `report.mjs` guarded `submission_status` with `firstLateSha !== lastOnTimeSha` and, twenty-five lines below, flagged the warning with the weaker `if (firstLateSha)` — so a finished exam cohort read `on-time` while every row also carried "late activity". An observation is a collector run, not a commit: re-reading an untouched repo after the deadline sets the two SHAs equal. `tests/report.test.mjs`.
- **Fail closed.** An unrecognised `roster_mode` is `enforced`; an absent nonce rejects; an absent `lock_down_enabled` is `true`. Never relax one of these to match a form default. The one deliberate exception is a field's own absence where absence has always meant *everything*: an assignment with no `cohort` admits every roster student, because every assignment predating the field has none and reading that as "nobody" would lock out every existing cohort.
- **The roster is org-wide; the cohort is per assignment, and it is a LIST, not a rule.** One `students/roster.yml` per org; an assignment stores the students picked from it and `lib/cohort.mjs` decides, nothing else. It holds **references** (`num:` / `login:`), never copies of student records — a second copy is how one student comes to exist twice and disagree with themselves. Matching accepts **either identity a row carries**, because a promoted row that gains a student number would otherwise stop matching a cohort it is deliberately in. `students/roster.yml` itself is `ROSTER_PATH`, never re-spelled (`tests/roster-path.test.mjs`).
- **When a rule says "match on ANY of these", every surface reading that data obeys it — not just the gate.** `rosterIdentities` exists so a roster row named `login:ella-dev` still resolves after a CSV import gives it a student number. The acceptance gate used it; the cohort picker's checkbox asked `cohortSelected.has(cohortIdentity(s))` — one canonical key — so a student the gate admitted rendered **unticked**, and unticking her would have removed an identity that was not stored and left the real one behind. A relaxed match applied on one side only is worse than no relaxation: the screen and the gate disagree, and the screen is what a lecturer acts on.
- **A new identity form is added to `rosterIdentities` and to everything that reads one back, in the same commit — and the guard is derived, never a list.** `email:` was taught to the minter alone. `normalizeCohortEntry` returned `""` for the prefix it did not know and the assignment schema's `cohort` pattern refused it, so the picker minted an identity the save rejected with a raw regex — and had one been stored, the gate would have dropped it silently, the checkbox rendered it unticked, and `danglingCohortEntries` could not report it, being built from the same discarded set. **A cohort of only email-keyed students normalises to empty, and empty means the whole roster**: a fail-open, under the very `roster_mode: claim` where every student can be email-keyed. `tests/cohort.test.mjs` mints one identity per kind and requires each to round-trip the normaliser, admit its own row, and match the pattern read out of the schema at test time. Verifying against the live orgs is necessary and proves almost nothing on rosters of six students — it says no *existing* row changed, not that the new path works.
- **An identity a person TYPES can change under the row it names, and an edit that changes one is a removal everywhere else.** A number and a login are handed to this system; an address is typed, and a roster row carrying only an address is identified by it. Correcting a typo re-identifies the row, so every cohort holding the old spelling stops matching — a removal from a published cohort past the add-only rule, which cannot see an edit made on another tab. `lib/cohort-reidentify.mjs` says which assignments would lose the row and what to write instead; the Roster tab confirms, then carries them over. Roster write first, assignments after, and the failure names them — a cohort left holding the old address is a dangling entry, which `danglingCohortEntries` reports, not a silent one.
- **A check that guards a rule asks the function that decides it.** The per-row import check was `IDENTITY_COLUMNS.some((f) => entry[f])` — a truthy cell — while `rosterIdentities` discards an address it cannot normalise, so `email: "garbage"` imported a row with **no key**: exactly the row the check exists to refuse. Same defect as spelling a name in two files, at one function's distance.
- **Never clear what is on screen before you have its replacement.** `loadDashboard` emptied `assignments` at the top of every run and then returned early on two paths that also turned the spinner off, so a superseded run could leave the page with no list, no state and no spinner — rendering a sentence about an organization it had never read. Build into a local and assign once, or clear only where a branch is authoritative.
- **A message no branch computed is a guess, and it will eventually be a lie.** *"Assignments in this organization are closed or archived"* was the fallback for an empty list with no state set — while closed and archived assignments are IN that list, so it could never have been true. It was shown over six published ones. Say what the code actually established; where it established nothing, say that.
- **A gate belongs where its question can be answered, and a gate that cannot narrow will be routed around.** The assignment form refused a name over every repository in the organization the pattern would produce — and could not know who would *accept*, which is the half that decides whether any of them matters. A real course was refused over 300 portfolios from previous years of which perhaps two belonged to a returning student, and offered "delete 300 students' repositories" as one of two ways forward. No wording fixes that, and neither does narrowing to the roster: the org had none, which is ordinary under `roster_mode: open`. `acceptance/accept.mjs` step 7 asks it with both halves in hand — this student, this name — after the `already-accepted` branch has excluded a retry and `isFirstMember` a group member joining a teammate's repository. What stays at creation is what creation genuinely settles and nothing downstream re-asks: the pattern clash and the surviving archive. The tell that it was in the wrong place was already there — the refusal was bypassable by saving under another pattern and editing it back, which is the natural move for a lecturer who has been told no, and the edit path re-asked nothing. `lib/existing-repo.mjs`, `lib/assignment-collision.mjs`.
- **A 403 can be a plan gate rather than a permission failure, and the two mean opposite things.** Measured 2026-09-09: `GET /repos/{o}/{r}/rulesets` answers `200 []` on Team, and **403 "Upgrade to GitHub Pro or make this repository public"** on a free organization's *private* repository (`200 []` on a public one; the org-level endpoint says "Upgrade to GitHub Team"). Reading that as *unreadable* — the fail-closed instinct — refused every student on a free organization whose repository already existed. Where a feature is plan-gated, its absence is an ANSWER: no ruleset can be enforcing, so nothing is frozen. It is doubly safe here because the lock would have been written by the same App with the same token, so a token that cannot read one cannot have created one. A 401 or a 500 is still nothing. `frozenFromRulesets` takes the status, not a boolean, so the distinction can be expressed. Ask the live API what an endpoint returns on **each plan** before deciding what a failure means.
- **A generated name proves ownership only when it embeds the owner.** `portfolio-{github_login}` produces `portfolio-PXL-AnnDeWit`, which can only ever be Ann's — so handing an existing one back is safe by construction. `grp-{team_slug}` produces `grp-team-a`, and teams are per assignment (`teams/<id>/<slug>.json`) while **the repository name is not**: it carries the slug and no assignment id, so every assignment that ever had a `team-a` makes that same name and each one's members were different students. Reuse there gives this year's team another cohort's repository with their work in it, which provisioning has done silently since it was written; slugs repeat every year because repeating is what they are for. So an absent `existing_repo_policy` resolves by `assignment_type` — `reuse` for individual, `refuse` for team — **derived, never written**, so an explicit answer still wins, and the dialog is not offered on a team assignment because there is no choice to make. The general form: before reusing anything a pattern produced, ask what the pattern actually pins. `lib/existing-repo.mjs`.
- **A protection guards the case you were thinking of, not the dangerous one — check the other direction.** Add-only stopped a lecturer removing a student from a published cohort. It did nothing when the assignment had *no* cohort, so the picker cheerfully narrowed a live assignment from the whole roster to whoever was ticked, refusing students who already held repositories. Measure the unprotected case before believing the protection.
- **A schema field with a reader and no writer is worse than a dead field.** It reads as a supported feature, so the next person adds a writer for it — somewhere else — and now one fact lives in two places that disagree. `students[].teams` was a per-assignment map read at every group acceptance and written by nothing: not the CSV import, not quick add, not promotion, not seeding. Delete the field *and* the read. `students[].team_slug` beside it was the opposite failure — it worked, and carried **no assignment**, so one slug pre-assigned a student in every group assignment the org ever ran. Team membership is `teams/<id>/<slug>.json` and nothing else; the roster column is a seed `lib/seed-teams.mjs` reads once.
- **A control that saves on blur and cancels on escape must make the cancel win.** Cancelling unmounts the input, the unmount fires `blur`, and `blur` saves — so Escape cleared the draft and the blur behind it wrote the cleared value, removing the class group the lecturer had just decided not to touch. Guard the save on the edit still being open. The test that catches it is "an unchanged value writes nothing", not the one about escape.
- **`class_group` gates nothing. It is a filter.** It was the gate until 2026-09-05, and being a rule meant the cohort was never written down and could only slice one way — "3A plus these four" had no expression. `lib/class-groups.mjs` holds only what a picker needs now. A `cohort_groups` label was tried and removed — it named the groups *represented* in a selection, so three students who shared one made a card claim the class. If a surface needs to know who is admitted, it asks `lib/cohort.mjs`; if it needs a headline, it uses the count.
- **Merge, never replace.** A document rebuilt field-by-field from what a form shows drops whatever nobody listed. Read the stored document, spread it, override only what changed — and validate before committing.
- **One source of truth per cross-surface concern.** Don't fork a shared `lib/` module into a second implementation; the tests fail if you do.
- **A guard over two lists is exhaustive, not comparative.** Two surfaces exported the same report from two hand-written 35-column lists that were not the same 35 — the SPA dropped `claimed_email`, `claim_verified`, `claim_domain_allowed`, `archive_repo` and `archive_ref`, and ten more row fields were in neither with nothing recording it as a choice. Comparing the two lists would only have found the first half. `lib/report-csv.mjs` splits them into exported / join-only / excluded-with-a-reason, and `tests/report-csv-columns.test.mjs` requires every field the schema declares to be in exactly one — so a new field fails until someone decides. The test that "covered" this had **copied** the header list and `csvCell` into itself and asserted against its own copy, which had already drifted.
- **An escape and its inverse are one pair, in one file, round-tripped by a test.** Export CSV guards a cell starting with `= + - @` with an apostrophe so a spreadsheet cannot execute it; nothing stripped it back off, so export → edit → import silently changed the value — on the round trip the Roster tab itself recommends. Three byte-identical copies of the escape existed (`RosterTab.vue`, `AssignmentDetailView.vue`, `report.mjs`) and not one owned the inverse, which is exactly how a half-rule survives. `lib/csv-cell.mjs`, `tests/csv-cell.test.mjs`. The inverse undoes **its own rule and no more**: stripping every leading apostrophe renames `'t Hooft`, and this runs on rosters of Flemish students.
- **Identical names over different constants are not a fork.** Two modules may legitimately declare the same name at different sizes — the guard's job is to stop the merge, not perform it.
- **A guard whose anchor was renamed checks nothing, silently.** `indexOf` returns -1 and `slice(-1)` still returns a string, so an absence assertion passes vacuously.
- **A generated document with no schema is a document no test can reject.** The e2e fixture validates every control-repo write against the schema for its *path*, so a path nothing declares is exempt in silence — `CONTROL_PATH_SCHEMAS.find()` returns undefined and the write is stored. `reports/dashboard.json` had three writers and no schema, and the exemption sat in the fixture as a comment for months. Both halves of the write path are checked now, `PUT /contents` and the Git Data API tree; a multi-file commit is refused whole. Give any document more than one surface writes a schema, and check it against the live orgs before believing it.
- **A record nothing regenerates has to be self-contained, and every repository in it is `owner/name`.** `retired/<id>/manifest.json` is written once, by one commit, and no later run will correct it. It named the broker as `owner/name` and the archive as a bare repository name, leaving a reader to infer the org from the one document whose purpose is to need no context — and it got there by calling `archiveRepoName` (where a *new* archive goes) for a question about where one *is*, with a comment arguing that was correct. It is not: a cohort preserved before per-assignment archives is in the legacy per-org one, so the answer comes from the report's preserved rows (`reportArchiveRepo`). `lib/retired-manifest.mjs`, `tests/retired-manifest.test.mjs`.
- **A record that cannot be updated states what was true when it was written, and how much was at stake.** The archive outlives the assignment on purpose and the lecturer deletes it by hand at the end of the year — nothing tells the manifest that happened and nothing can, so `archive_deleted_at` would be permanently absent and mean nothing. `preserved_submissions` is the field that works instead: a count taken on the day, so a 404 years later separates a deliberate cleanup (`0`, nothing was in it) from a name recorded wrongly. Prefer a fact the writer can establish over a field a future human is trusted to set.
- **A mock that accepts anything tests nothing.** Fixtures validate what the app writes against the real schema — and a fixture must be the shape the app *actually writes*, not one the test invented. A lockdown test built one team-shaped repository record where production writes one per login; a "contract" test reimplemented `buildDoc()` and drifted past the signed-acceptance keypair. Both passed for months against code that could not work.
- **A click handler that copies, opens a window or goes fullscreen must not `await` first.** After an `await` the engine stops *attributing* the call to the handler, so the clipboard write is refused and the pop-up is blocked — in Firefox, while Chrome forgives it, which is how it ships green and breaks in production. Do the synchronous thing inside the gesture; spend the async API only when there is nothing left to lose. `tests/device-flow-clipboard.test.mjs`.
- **Never set a success flag before the operation resolves.** `ok = true` beside an un-awaited promise whose rejection goes to `() => {}` is a UI that lies. It cost sign-in: the device-flow button reported "Copied" over an empty clipboard, so students had no code to paste. Await it, or report failure.
- **A guard that greps for a branch cannot tell it is reachable.** The test for that button asserted an `else toast…` branch existed. It did, and it was dead code. Extract the logic and run it.
- **`.catch()` on a function that resolves is not error handling, it is the look of it.** Everything in `frontend/src/lib/api.js` resolves `{ ok: false, status }` rather than throwing, so a `.catch()` chained to one never runs. Read `.ok`. `tests/button-honesty.test.mjs` sweeps for it.
- **Never re-implement the thing under test in the test.** Import it. If it cannot be imported, that is the defect.
- **Never describe behaviour the system does not have.** A control that promises a queue, a retry or a guarantee nobody implemented is worse than no control.
- **A stored value is not a label** (DESIGN.md §1.7, `tests/status-labels.test.mjs`). `{{ s.submission_status }}` printed `no-submission` at a lecturer and `{{ s.acceptance_state }}` printed `provisioned`, a word only this codebase uses; the assignment state reached a *student* raw. Enum fields get a label map in `frontend/src/lib/status-labels.js`, checked against the schema, falling back to the raw value rather than a blank. Display only — `lib/report-csv.mjs` still exports the stored words. And a column heading is not repeated in its cells: an empty **GitHub Account** cell is a dash, not `Pending linking`, and never `No address`, which is the Email column's answer one column to the left.
- **The UI never points a user at the repo's documentation** (DESIGN.md §1.6, `tests/doc-refs.test.mjs`). The runbooks are for whoever operates a deployment; a student who cannot sign in is not that person. Say what happened and who can fix it. Comments are exempt — that is where a `§` reference belongs.
- **Dry-run is sacred.** Every CLI `--dry-run` has zero side effects — no writes, no PRs, no commits.
- **Generated YAML is serialised, never concatenated.** Build an object, hand it to the `yaml` library. One exception, and it is forced: `scripts/register-participating-org.mjs` appends to `participating-orgs.yml` by hand, because `setup-org.yml` deliberately runs with **no `npm ci`** and so cannot have the `yaml` library. It is confined to that one script, both logins are validated against `^[A-Za-z0-9](-?[A-Za-z0-9]){0,38}$` beside the write, and `tests/register-participating-org.test.mjs` parses what it produces with the real `yaml` library and validates it against the schema — which is the check the rule exists to give you.
- **No inline JavaScript in workflow YAML** — `node -e`, `node -p`, `--eval`, `--print`. Extract to `scripts/`. eslint cannot see it, the tests cannot import it, and every value in it arrives by *shell* substitution into the source text.
- **The assignment id is not the collision key — `repository_name_pattern` is**, and the question is always what still *exists*. Provisioning is idempotent on repository existence, so a pattern producing a name that is already there hands the student the old repository with the old deadline's lockdown ruleset on it; `lib/seed-teams.mjs` stated the invariant for a year and nothing enforced it. `lib/assignment-collision.mjs` is the judge. Ask the org's repository listing, never the deletion record: `retired/<id>/` is written by *every* delete, so blocking on it refuses "I opened it, nobody joined, starting over", and a lecturer who cleans up must be believed. The surviving archive blocks too, because `preserve.mjs` pushes without `--force` — that one fails at the *next* deadline, not at the click.
- **A join has two sides, and the one you did not write is the one that matters.** `planClaimPromotion` matched a claim to a roster entry with `byEmail.get(entry.email)` — the roster supplies the address, the system learns the login. A row promoted from an acceptance has no address, so the lookup missed every one of them, while the claim right there carried the `github_id` and `github_login` that row is keyed by. The only rows that could not be identified another way were the only rows the claim could not reach. Match on the id first, the login second; hold an address another row already holds (that field IS the join) and one outside `claim_domains`.
- **A preview and the write it describes are ONE document.** `diffRosters` returns `merged` and both importers commit *that*, because "preview here, build your own document there" is how a diff and a write come to disagree. Its matching obeys `rosterIdentities` like everything else: a CSV row always carries a number (`rowsToRoster` requires one) so it keyed `num:`, while a promoted row keys `login:` — the import **added one and removed the other**, and where the CSV had no `github_login` column the login was gone. Merging is safe *because* `coerceCell` omits an empty cell, so a CSV cannot express a deletion; removing a student is what the confirmed `removed` list is for. A login is now identity-bearing on that path, so two CSV rows sharing one are refused like two sharing a number.
- **Showing a value and storing it are different decisions, with different rules.** A promoted roster row has a login and nothing else, and nothing fills it in later — promotion skips rows it has seen, and a claim joins on `email`, which such a row lacks. `lib/roster-harvest.mjs` reads what the collector already knows and **shows everything** except what merely repeats the login (`IlkayDuranPXL@github.com` beside `@IlkayDuranPXL` is the login twice), while **writing only** what `domainAllowed()` accepts — `email` is the claim join key, so a wrong one there rejects that student at acceptance. `rayane.waddah@student.pxl` is the case: a typo'd domain that is unwritable and is still the string that names the person, so it is shown and flagged, never hidden. Names are never written at all: a commit author is a username as often as a name, and unlike a blank it looks filled in.
- **A finalize run is not once, so anything it undoes must be recorded where it looks.** `find-finalizable.mjs` re-queues an assignment while preservation is incomplete **and when any student's deferred extension expires**, and `planTargets` builds from every record — so a second pass re-locked a repository a lecturer had deliberately reopened, triggered by granting somebody *else* more time. Lockdown reads `lockdowns/<id>/unlocked/` and skips those repositories, matched over `teamMembers` because a group repository is one object with one lock. An unreadable record counts as reopened: failing the other way locks out a student who was let back in.
- **Two writers of different trust on one field need the field to say which.** `email` is filled by a claim (GitHub-verified) and by the harvest (a git-config address). `email_source` records it — absent means a person, which outranks both — and every writer that sets the address sets or clears it, including the inline edit and a CSV that changes it. A stale provenance marker is worse than none: it is confidently wrong.
- **A lock is a flag, not a fact — and its inverse is whatever locked it.** `enforcement` flips (`lib/submission-lock.mjs`); `releaseSubmissionLock` sends that one field and **never deletes** the ruleset, because a re-created one without the App in `bypass_actors` locks this system out too, and never *creates* one, because an absent ruleset means nothing is locked. Lockdown degrades to demotion **per repository**, so `lock_method` on the row decides which inverse — undoing a demotion with a ruleset flip reports success over a student who still cannot push. It restores the assignment's `student_permission`, because the record stores `permission_after` and never what came before. Refuse while preservation is `pending`; refuse *differently* when it `failed`. `lockdowns/<id>/unlocked/<login>.json`, written after the operation, one file per student because the lockdown record is rewritten whole by the next attempt.
- **Never compose an archive name or a `preserved/` URL yourself** — `lib/archive-repo.mjs` decides where a preservation *is* versus where a new one *goes*.
- **Every deadline comparison is the deadline for *that student*** — `lib/effective-deadline.mjs` decides, nothing else.
- **`observed_at` is when the collector looked, never when the student acted.** Deadline classification compares the **commit's own** timestamp; the observation time is a fallback for records that predate `commit_date`. Comparing observation time to the deadline marked two students late on a finished exam for committing 6h50m and 54m *before* it — it can only ever err in that direction, and only against students who work up to the deadline. `lock_down_at` was moved off the observation for this same reason; the rule is the field, not the one call site.
- **`max_acceptances` can overshoot, and that is a decision.** Do not "fix" it by serialising every acceptance.
- **A rejection is an outcome, not a failure.** `rejected:*` exits 0; only `fail:*` goes red. **And it has to be visible where the lecturer is** — for years the only surface was a comment on the control repo's tracking issue, so an assignment refusing exactly the people it was configured to refuse looked, on screen, like a broken invitation link. The detail view reads it (`lib/rejection-notice.mjs`), from the **dedup key** rather than the prose beside it — that key is what the notifier already matches byte for byte, so it cannot drift without dedup breaking first, and `tests/rejection-notice.test.mjs` checks the workflow's literal against the builder. A new `rejected:*` with no human label fails that test rather than showing a lecturer a slug.

## Frontend

- **Theming is token-only.** Every colour is declared once in `frontend/src/style.css`'s `:root` as `light-dark(...)`. No colour literal anywhere else, and no `var(--token, #fallback)`.
- **If more than one component uses a class, it belongs in `style.css`.** Scoped styles cannot reach slot content, and an undeclared class renders unstyled with no build error.
- **An isomorphic module takes configuration as a parameter and never imports it.** A static `node:` builtin import in the SPA's graph is a blank page that `npm run build` will not catch.
- **A route nothing links to does not ship.** Exactly two exemptions exist (`invitation`, `not-found`); the list may not grow without writing down why.
- **A published field is a public field.** Anything in an assignment's `title`/`description` reaches GitHub Pages; `lib/public-text.mjs` is the one judge.
- **A prop the child never declared is a DOM attribute, not configuration.** It falls through silently, and a same-named computed inside the child keeps winning — the Sandbox asked `<TeamsTable>` for the autograde variant twice and previewed the plain one. Drive the child's own inputs; `vue/no-undef-properties` and friends are errors now.
- **A wrapper that holds a modal may not carry a transform.** `transform`, `filter`, `perspective`, `will-change` or `contain` on ANY ancestor makes it the containing block for `position: fixed` descendants, so `.modal-overlay { inset: 0 }` sizes to that ancestor and the dialog renders `scrollY` pixels off-screen — a button that looks dead. `fade-in` is the trap: it ends on `translateY(0)` with `animation-fill-mode: forwards`, and an identity transform is still a transform. `tests/e2e/47-modal-in-viewport.spec.mjs`.
- **An inline editor may not change the size of the cell it opens in.** Leaving one closes it on *mousedown*, so the layout settles before the mouseup and the click lands on whatever slid into the gap — clicking straight from one open cell to another opened nothing. Row height was innocent; the *column* moved 44px, because `<input>` carries an intrinsic width from `size` (~20 characters) and an auto-layout table sizes columns from intrinsic contributions, where a percentage counts as auto — so the column grew to fit a box already set to `width: 100%`. `size="1"` is the half that matters. Measure a cell in another row *and* another column, both axes; the arithmetic over borders, paddings and a negative margin is in the wrong dimension. `tests/e2e/63`.
- **The keystroke that opens a control must not be the one that commits it.** A `<button>` activates on Enter's *keydown*, so opening a cell from the keyboard mounts and focuses its input while that key is still down — and the keyup commits, in a box the person has not read. Listen on `keydown` inside the control. Related: a `v-if` swap of button→input leaves focus on the removed element, so focus it on mount — and note that Playwright's `fill()` focuses for you, which is how eight tests passed over a cell a human had to click twice.
- **A suggestion is not an answer until a person accepts it.** A pre-filled draft is committed by Enter — a keystroke aimed at that cell — and never by blur; clicking a cell and clicking away must leave the row as it was. It fills a blank only, never overwrites a stored value, and accepting one clears the provenance marker the *bulk* path writes, because that marker records whether anybody looked.
- **Nothing throws at module scope** in a file the SPA imports — a throw there is a blank page.
- **One primary button per view** (DESIGN.md §1.2), and never invent a `.btn-` variant that DESIGN.md does not define.
- **The three big components are deliberately not split.** `AdminView.vue` (5,061 lines), `AssignmentDetailView.vue` (4,365) and `RosterTab.vue` (3,036) are the first thing any reviewer reacts to, and the answer is no — not "not yet". They hold the assignment editor, the cohort table and the roster: the surfaces that run exams, where a refactor's failure mode is a silent behaviour change, and where the tests would move with the code rather than catch it. The cost is real and is accepted: reading them is slow, and `editing.value` holding `{ id }` rather than the assignment document has already misled someone who assumed otherwise. What would justify revisiting: substantial new features landing inside them, or more than one person working in them regularly. Not their size on its own. **Do not add a line-count ratchet either** — it fails on legitimate feature work, which punishes the wrong thing. Fixing a specific defect inside these files is always fine; that is not what this rule is about.

## Shape of the system

Detail in [ARCHITECTURE.md](ARCHITECTURE.md); these are the facts that change how you write code here.

- **Target platform is GitHub Team for Education. Never Enterprise.**
- **Hub-and-spoke.** All workflows live in the public `pxl-classroom` hub. Per-org control repos hold data only and contain **no** workflow files.
- **Minimal-minutes.** Synchronous provisioning, one nightly cron that disables itself when nothing is active, event-driven dashboard regeneration. The system bills zero minutes when idle — do not add polling or marker-file triggers.
- **Two GitHub Apps.** *Provisioner* does the work and is installed on every org; *Broker* does one dispatch and is installed on the hub repo alone. Never widen the broker App.
- **Sign-in needs a CORS proxy and there is no third-party substitute.** The PXL-owned Worker is **primary**; whatever answers sees the access token.
- **Everything institution-specific is in `deployment.yml`, and it is data.** A fork edits that file and nothing else.
